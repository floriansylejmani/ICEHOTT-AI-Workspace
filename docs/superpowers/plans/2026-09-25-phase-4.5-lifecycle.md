# Phase 4.5 Tool Lifecycle Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bound tool execution time, allow safe cancellation, and make abandoned Running rows visible without repeating uncertain writes.

**Architecture:** Extend the domain state machine first, then persist deadlines/leases and guard transitions with the existing optimistic concurrency token. The execution service will use a bounded cancellation token and a separate recovery worker will mark expired Running rows OutcomeUnknown without invoking handlers.

**Tech Stack:** ASP.NET Core/.NET 9, EF Core, PostgreSQL, xUnit.

**Spec:** `docs/PHASE-4.5-SECURITY-DESIGN.md`

## Global Constraints

- Maintain workspace membership and permission checks for every endpoint.
- Preserve idempotency and at-most-one handler start.
- Never auto-retry a write with uncertain outcome.
- Never persist raw handler exceptions or secret inputs in audit events.
- Coordinate service/policy changes with Claude Packet B before service integration.

## Review Focus

- Cancel versus approve race: only one transition wins and no second handler starts.
- Timeout versus successful side effect: a terminal failure must not disguise a committed external write.
- Lost process: expired Running becomes OutcomeUnknown without handler invocation.
- Repeated cancellation and terminal retries: stable invalid_state with no extra audit event.
- Cross-workspace cancellation: no existence or argument disclosure.
